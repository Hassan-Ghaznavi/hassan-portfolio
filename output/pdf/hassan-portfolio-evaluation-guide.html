Your project in one minute

Hassan Ghaznavi | The Manual Is Wrong | Evaluation handbook | 25 November 2026

This guide explains the actual portfolio source, the files to open during evaluation, how its 3D and backend features work, and the security controls and limits. It is a preparation handbook, not a claim that every semester deliverable is finished.

Three distinctions to remember

Architecture and request flow

Browser → Vercel API → Google Gemini / Resend / Redis. Responses return through the API.

What happens when the site opens

The browser receives index.html, styles.css and ES modules. An import map resolves the bundled Three.js runtime. Project modules create their sections from local data. IntersectionObserver delays expensive viewers until nearby or visible; videos load only after a visitor requests playback.

What is deployed as the backend

api/chat.mjs and api/contact.mjs are serverless Node handlers deployed by Vercel from the repository. They are not copied into the static dist folder. Vercel routes /api/chat and /api/contact to those handlers. There is no separate always-running Express server or separate backend URL.

What is not a portfolio database

MongoDB, Supabase, Firebase and SQL Server appear as Hassan's skills or as technologies used inside showcased games. This portfolio itself does not use them to store visitor chats or contact submissions. Redis is used for counters and public embedding cache; Resend handles email.

The sketchbook interface

Visual vocabulary

Warm paper, graphite outlines, red corrections, hand-drawn diagrams, mounted photographs and small 3D objects create the manual theme. The latest framing uses irregular soft corner radii, subtle mount shadows, tape on awards, pencil inset rules and ruled expandable notes. These effects do not generate replacement artwork or blur authentic screenshots.

Reading and navigation

The manual opening is CSS 3D with a skip button. Session storage suppresses repeated automatic openings in the same session. Replay clears the hash and returns to the start before opening again. The reading line reflects the actual scroll position. Chapter search and the CV download remain independent of the 3D scenes.

Light and night paper

preferences.js reads a saved explicit theme. A visitor without a saved choice starts in light mode, even if the device prefers dark. CSS custom properties set paper, ink, accent and line colors. Night mode changes surfaces and text, rather than applying a global darkening filter to photographs. Paper grain remains visible.

Interactions are placed in context

  • Paper Plane Dash keeps the Unreal project information, gameplay and small browser flight interpretation together.
  • The whale belongs to Sunken Greed. Doodle stays at bottom right as the portfolio guide.
  • Opening the AIRIDEV book reveals projects. Bookmarks and source links can reveal a target even when the book was closed.
  • Film sketch reveals and real wireframe comparisons use sliders; horizontal dragging does not replace normal vertical page scrolling.

Accessibility

Semantic headings, labeled inputs, buttons, alt text, focus styles, keyboard sliders, Escape close behavior and live status regions support navigation. prefers-reduced-motion bypasses the introduction and reduces motion. This is practical accessibility work, not a claim of a complete WCAG audit.

Scroll scenes and performance

How scroll controls an object

The scene measures its section with getBoundingClientRect, maps its position to a clamped progress value from 0 to 1, and uses that value for transforms. The whale links section progress to travel; delta-time smoothing reduces abrupt jumps. The Blender study figures similarly drive forest growth, perfume-cap lift and cube-layer turns. A manual range control can override progress; Follow my scroll restores automatic control.

Why a shared renderer matters

mini-scenes.js uses one transparent fixed canvas with viewport and scissor regions. Each card still has a separate scene and camera, but only its matching part of the shared canvas is drawn. This avoids a separate WebGL context for every card. The avatar, whale and Doodle have separate viewers with different lifecycles.

Where the budget is saved

  • IntersectionObserver tracks visibility; hidden tabs and offscreen viewers stop work.
  • Dynamic imports delay large scene code and GLB loading. Videos use click-to-load, not automatic full downloads.
  • Miniatures cap pixel ratio at 1 on small screens and 1.25 on larger screens; avatar caps are 1.25 and 1.5. The whale cap is 1.4.
  • The avatar uses a modest 30 fps budget on small screens; desktop follows display frames. Other scenes use their own visibility and motion policies.
  • WebP assets reduce media size. YouTube embeds load on request. Pause controls and reduced-motion behavior avoid unnecessary movement.

Be precise about performance

These are optimizations in the source, not a universal 60 fps guarantee. A 390px responsive browser check is not equivalent to profiling a physical phone. Device GPU, thermal limits, scroll behavior and browser UI can still affect rendering.

Doodle RAG step by step

  • 1. Source selection: portfolio-notes.js holds approved facts about projects, contribution, skills, education and achievements. Raw private project folders are not indexed.
  • 2. Chunking: makeIndex splits each note into windows of up to 140 words, stepping by 100 words. Longer notes therefore overlap by 40 words. Many present notes fit in one chunk.
  • 3. Corpus embeddings: gemini-embedding-001 turns source title plus chunk text into 768-dimensional document vectors using RETRIEVAL_DOCUMENT.
  • 4. Query embedding: the current question is embedded with RETRIEVAL_QUERY. No full chat history is sent.
  • 5. Ranking: cosine similarity ranks vectors. A small 0.06 boost favors chunks also found by lexical retrieval. Results scoring at least 0.3 are limited to the top three.
  • 6. Generation: gemini-3.5-flash-lite receives system instructions, the question and retrieved source chunks. It is asked for short English answers in structured JSON.
  • 7. Validation: the handler checks answer shape/length and retains only source IDs from retrieved context. Factual responses without a valid retrieved citation are replaced by an unknown-information reply.
  • 8. Display: the browser renders text with textContent and approved internal source links. Clicking a source takes the visitor to the relevant portfolio chapter.

Where the vectors are stored

The active vector index is an in-memory array per function instance. Redis caches the approved corpus vectors for 24 hours, keyed by a SHA-256 hash of the corpus, model and dimensions. Redis here is not performing a vector similarity search; the function performs cosine ranking. A changed corpus produces a different cache key.

Cosine similarity is dot(query, document) divided by the product of their lengths. Lexical recovery normalizes TF-IDF vectors: frequent local terms are weighted, common corpus terms are downweighted, and results above 0.16 are limited to three chunks. This is distinct from semantic embeddings.

Explain RAG as retrieval plus generation. It is not fine-tuning: Hassan's documents do not retrain the Gemini model.

RAG grounding and failure recovery

Guardrails around model behavior

System instructions limit factual claims to the retrieved notes and prohibit inferring unsupported personal details or solo credit. The question and sources are serialized as data. JSON output requests responseType, answer and sourceIds. Conversation mode allows brief social exchanges; portfolio answers require supporting retrieved IDs. The model is not given tools to access files, execute code, browse arbitrary URLs or send email.

Three paths you must distinguish

PathWhat really happens
Normal vector RAGEmbedding succeeds, cosine ranking selects context, Gemini writes the response.
Server keyword recoveryA transient embedding problem triggers normalized TF-IDF retrieval; Gemini still generates from the matched public notes. Authentication and quota failures are not bypassed.
Browser saved-note fallbackIf generation/API communication fails, companion.js may show the matching saved note, labeled From my saved portfolio notes. This is retrieval only, not an LLM answer.

Why Gemini can pass once and fail later

Earlier diagnostics showed 503 responses and timeouts. A working key does not guarantee capacity or quota. The code allows at most two attempts per provider operation for selected transient HTTP failures and timeout/abort errors, with about one second of backoff and jitter. It does not automatically retry quota or authentication failures. The provider budget is 42 seconds; embedding work has a smaller 9-second budget. The browser POST timeout is 55 seconds.

The API returns 429 for free quota exhaustion or throttling and a recoverable 502 for generation/provider failure. Retry AI answer is user initiated. No paid fallback is enabled. GET /api/chat only indicates configuration readiness; it does not prove Gemini is responding.

Citation validation checks membership, not semantic truth. A valid source ID does not mathematically prove every word of an answer. Prompt injection risk is reduced, not eliminated.

Email from form to confirmed receipt

Frontend sequence

The browser checks form validity, collects name, email, subject and message, and adds a request UUID, form start time and honeypot field. contact.js posts JSON to /api/contact. Preview paper fold is visual only and never sends the note.

Server sequence

  • Check allowed origin, content type, payload size and field bounds. Reject header newlines, filled honeypot or implausible form timing.
  • Apply shared Redis and per-instance contact limits. Build a plain-text email with a fixed configured recipient and sender. The visitor's email is reply_to, not the sender identity.
  • Call Resend server-side. A hash of request UUID plus message fields becomes an idempotency key, reducing duplicate sending when the same accepted request is retried.
  • Return HTTP 202 with a signed receipt containing only provider email ID and timestamp. Acceptance is not treated as confirmed delivery.
  • Poll delivery using that receipt. The browser makes up to ten status checks. The handler maps provider events into pending, delivered or failed. The paper folds only after delivered/opened/clicked is reported.

Receipt protection

HMAC-SHA256 signs the receipt using the server-side Resend key. timingSafeEqual compares signatures. Tokens expire after ten minutes and future timestamps are bounded. The signature prevents changing the email ID to enumerate arbitrary messages. The token is signed, not encrypted: treat it as a short-lived bearer capability.

Delivery means the receiving mail server accepted the email; it does not guarantee primary-inbox placement or that a human read it. Pending/failed states preserve the note and avoid claiming success. The app does not implement a general contact-message database.

Sending limits are 4 valid POST requests per ten-minute per-IP window. The receipt GET route is token protected but does not currently use the same shared rate limiter; this is a remaining hardening opportunity.

Hardening opportunities, not completed features

  • Add verified bot challenges only if abuse justifies them; Cloudflare is optional infrastructure, not a prerequisite for Vercel functions.
  • Consider receipt polling throttling, a separate receipt signing secret and tighter provider credential scopes.
  • A stronger CSP requires inventorying inline import maps, remote fonts, frames and WebGL-related needs before enforcing script/connect/font restrictions.
  • Guardrails can reject unsupported IDs, but semantic support and prompt-injection resistance need adversarial evaluation. Broader hardening should be a separate measured change.
  • Review provider project billing/privacy settings and credential rotation privately. No local code flag can guarantee an external account's settings.

Do not tell the examiner that Redis, origin checks or a private env file alone make the system fully secure. Explain the threat each control reduces and the cases it does not cover.

Questions your examiner may ask

Why Three.js instead of only videos

Three.js lets the viewer explore real geometry and lets scroll/pointer input change objects at runtime. Videos are used for authentic project footage; they cannot replace interactive scene transformations.

Is Doodle just a hard-coded chatbot

The normal API route performs embeddings, retrieval and Gemini generation. A separate browser fallback searches saved notes when the provider fails. The fallback is explicitly identified and is not presented as an LLM response.

Where is the vector database

The small corpus is searched through an in-memory vector index. Redis persists cached corpus vectors for 24 hours; it does not run vector search. A dedicated vector database would be a future scaling choice, not a current dependency.

How do you avoid invented facts

Curated source notes, scoped instructions, short structured answers and retrieved-source ID validation reduce unsupported output. Unknown information is acknowledged. These measures improve grounding; they are not a proof that every answer is correct.

Where is the backend deployed

Both api handlers deploy as Vercel Node functions from the same repository. The frontend is generated into dist. The production hostname routes API requests and static assets without needing a separate server URL.

Can someone steal the key from the browser

The browser calls my API, which reads credentials server-side. Public assets do not contain the keys. This protects direct disclosure, while rate limits and validation reduce misuse of the public endpoint. Exposed keys still need revocation and rotation.

What is original and what is credited

The custom Hassan avatar and procedural scene motifs are portfolio work. Doodle's pencil comes from a credited CC BY asset. Team games retain team credit and specific contributions. Internship projects show only approved screenshots. Be transparent about AI/automation assistance if asked.

Useful HTTP meanings

400 invalid input; 403 wrong origin; 405 method not allowed; 413 body bound; 415 non-JSON; 429 throttle/quota; 502 upstream/response failure; 503 unconfigured or temporarily unavailable dependency. Exact route messages determine which condition occurred.
